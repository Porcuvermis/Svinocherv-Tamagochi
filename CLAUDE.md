# Свиночервь Тамагочи — рабочие правила

Мобильная HTML5-игра: тамагочи, где потребности персонажа — семь смертных
грехов, у каждого своя мини-игра. Чистая статика, сборки нет.

## Куда игра едет

Целевая картина, экономика и метапрогрессия: **`docs/plan/`**. Начинать
чтение с `docs/plan/05-next-steps.md` — там разбор плана и порядок работ,
остальные файлы тематические.

Игра станет Telegram Web App с серверной частью. Сервера пока нет, но код
пишется под него: см. правила ниже.

## Инварианты (нарушение = переписывать потом)

1. **Никаких тикающих таймеров состояния.** Значение шкалы, оффлайн-доход,
   кулдаун — всё считается формулой от `updated_at` и текущего времени, а не
   накручивается в `setInterval`. Таймеры на клиенте — только для анимации.
2. **Мини-игры ничего не начисляют.** Они сообщают результат
   (`sin`, `mode`, `outcome`, `meta`), а что за это дать — решает конфиг
   наград. Прямые записи вида `GameManager.sins.X.value = 100` запрещены.
3. **Числа баланса живут в конфиге**, не в коде мини-игр. Конфиг потом
   переезжает на сервер как есть.
4. **Всё время — через `time.js`** и серверную поправку. Локальные часы
   игрока не источник правды.
5. **Состояние сохраняется с номером схемы и мигрируется.** Не сбрасывается
   при смене формата: на сейве висит прогресс, который копился неделями.
6. **Координаты всего, что живёт на теле** (шрамы, косметика, следы грехов) —
   нормализованные, привязанные к скелету (`zone` + `t`), не в пикселях.
   Иначе всё поедет при взрослении и эволюции.
7. **Игра обязана открываться без Telegram.** Нет `initData` → локальный
   игрок. Это штатный режим, на нём идёт вся разработка и тестирование.

## Структура

```
index.html          точка входа, подключение всех модулей
main.js             сборка HUD, маршрутизация по экранам (состояния НЕ хранит)
style.css           общие стили, safe-area
boot.js             версия сборки, service worker (не игровая логика)
sw.js               кеш сборки: отдаёт мгновенно, свежесть — через смену sw.js

src/config/economy.js   ВСЕ числа баланса: скорости шкал, награды, цены
src/core/boot-screen.js экран загрузки: когда открывать (сама пелена —
                        инлайном в <head> index.html, без единого запроса)
src/core/events.js      шина событий (мини-игра → ядро)
src/core/time.js        серверное время и ленивый расчёт шкал
src/core/state.js       состояние игрока, форма повторяет будущую схему БД
src/core/backend.js     переходник к «правде»: форма будущего API,
                        единственное место, где что-то начисляется
src/core/worm-*.js      модель персонажа, рендерер, палитра
src/core/debug.js       debug-режим и машина времени для шкал

src/minigames/<грех>/   каждая мини-игра в своей папке: js + css
src/minigames/envy/     облако наклеек: пул образов, упаковка полотна,
                        векторные образы строкой (см. docs/plan/envy-cloud.md)
docs/                   заметки по персонажу и рендереру
docs/plan/              план развития: экономика, метапрогрессия, порядок работ
vendor/                 сторонние библиотеки (three.js), версия прибита в URL
tools/                  вспомогательные скрипты (иконки, launch-экраны iOS,
                        страница сборок, перевод картинок в SVG для
                        образов «Зависти»)
```

Порядок подключения в `index.html` важен: конфиг → события → время →
состояние → переходник, и только потом `main.js` и мини-игры.
Экран загрузки — исключение из правила «стили в css, логика в js»: его вид
(класс `.boot-veil` и стили к нему) написан инлайном в `<head>` index.html.
Причина в комментарии там же: всё, что подключается ссылкой, — это запрос в
сеть ДО первого кадра, а пока он идёт, экран белый.

Новая мини-игра — отдельная папка в `src/minigames/`, а не дописывание в
существующие файлы.

## Как это попадает на телефон

Пуш в любую ветку → GitHub Actions собирает и выкладывает на Pages → ветка с
самым свежим коммитом лежит в корне сайта, её открывает иконка на домашнем
экране. Мержить в `main` ради просмотра не нужно.

Подробности и разбор устройства: `docs/deploy-iphone.md`.

Шкалы падают за 8–48 часов реального времени, поэтому проверить их «вживую»
без отмотки нельзя: кнопка 🐞 включает debug-режим, там есть «−1 ч», «−8 ч»,
«Полные» и «Сброс». Отматывается не системное время, а метки в состоянии, —
то есть проверяется ровно тот механизм, что работает в игре.

Из этого следует одно требование к коду: **правка должна быть видна в
браузере**. Никаких шагов сборки, транспиляции и npm-зависимостей в рантайме
без крайней необходимости.

Версии ассетов (`?v=...`) в `index.html` вручную поднимать не нужно — при
деплое им проставляется общий номер сборки.

## Стиль

* Комментарии по-русски, по делу: **почему так**, а не пересказ кода.
  Особенно там, где решение неочевидно или было выбрано после провала
  другого варианта.
* Цвет берётся из `src/core/palette.js`. Хардкод hex в рендерере запрещён,
  правила — в `docs/art-direction.md`.
* Интерфейс без лишних кнопок: клики по самой сцене, графические крестики,
  понятные жесты. Подробности — в `README.txt`.
* В `README.txt` есть блок «Инструкция для ИИ» с требованием выдавать файлы
  целиком — он написан для чат-ассистентов без доступа к репозиторию. Здесь
  доступ есть, поэтому правки вносятся обычными точечными изменениями.
