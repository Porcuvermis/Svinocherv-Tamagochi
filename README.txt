## 📌 Суть проекта
Мобильная HTML5-игра в стиле Тамагочи с уникальным сеттингом. Главный персонаж — **Свиночервь** (Мы переходим на DOM-центричный подход:
1. SVG для статики: Рисуем все элементы (корпуса, кнопки, рычаги) через SVG внутри HTML. Это дает идеальную четкость на любом экране без потери качества.
2. CSS для динамики: Все «движения» (вращения рычага, прыжки барабанов, появление окон) делаем через ⁠transition⁠ и ⁠keyframes⁠. Это работает плавно за счет аппаратного ускорения (GPU).
3. Логика через классы: Теперь логика игры — это просто переключение классов (⁠active⁠, ⁠spinning⁠, ⁠pulled⁠).). Задача игрока — следить за состоянием персонажа, удовлетворяя его потребности, которые представлены в виде **7 Смертных Грехов**:
* Гордыня, Алчность, Зависть, Гнев, Похоть, Чревоугодие, Уныние/Лень.

## ⚙️ Игровая логика и дизайн-концепция
1. **Система потребностей (Грехи):**
   * Каждый грех имеет свой уровень (value) и скорость убывания (decay).
   * **HUD на главном экране:** Отображает быстрый статус потребностей. При клике на HUD открывается развёрнутое меню.
   * **Экран меню потребностей:** Развёрнутый интерфейс, где игрок видит детальный прогресс каждого греха и запускает тематические мини-игры.
2. **Философия UI/UX — "Минимум кнопок, максимум интуитивности":**
   * В игре минимизировано количество классических кнопок с текстом (вроде "Закрыть", "Крутить" и т.д.).
   * Интерфейс говорит сам за себя. Например, в меню вместо кнопок выхода используются понятные паттерны (красные стрелочки вверх, указывающие на закрытие свайпом/кликом), а в мини-играх — простой крестик в углу или вверху экрана.
   * **Окно мини-игры одинаковое у всех грехов** и собирается общим модулем (`src/core/minigame-window.js`): экран целиком, рамка с отступом от края цветом греха, крестик в правом верхнем углу шапки, вопрос «выйти?» при закрытии. Мини-игра рисует только своё содержимое — подробности в `docs/minigame-window.md`.
3. **Мини-игры:** Для каждого из 7 грехов предусмотрена **своя уникальная мини-игра**. Успешное прохождение восстанавливает шкалу соответствующего греха.

## 🕹️ Геймдизайн мини-игры "Алчность" (Слоты / Однорукий бандит)
* **Визуальный ряд:** На экране отображается классический игровой автомат. На нём нет лишних управляющих кнопок.
* **Управление:** Максимально простое — клик по любой области Canvas (кроме крестика закрытия) дёргает физический рычаг и запускает вращение барабанов.
* **Закрытие:** Единственный явный элемент управления — аккуратный крестик в верхней части экрана слотов, который закрывает мини-игру и возвращает игрока в меню.
* **Анимация победы:** При выигрышной комбинации проигрывается короткая простая анимация "фейрверка"" (разноцветные брызги), а на экране на пару секунд  появляется надпись "Нагрешил!", после чего плавно исчезает.

## 📂 Архитектура и масштабирование проекта

Чтобы проект не превращался в "файловую кашу", принята модульная структура. Код строго разделен по зонам ответственности:

* **`/index.html`** — Точка входа. Общая HTML-разметка игрового контейнера, экранов меню и контейнеров для мини-игр.
* **`/style.css`** — Глобальные стили приложения, адаптивная вёрстка под мобильные экраны (safe-area, viewport-fit) и стилизация основного интерфейса.
* **`/src/core/`** — Ядро игры:
  * `worm.js` — Отрисовка Свиночервя на Canvas, его физика, анимация движения, моргание и детали тела.
  * `main.js` — Инициализация, игровой цикл (tick), расчёт убывания потребностей, обновление HUD и общая маршрутизация между экранами.
* **`/src/minigames/`** — Каталог мини-игр. **Каждая мини-игра изолирована в своей отдельной папке**, где лежат её собственные JS, CSS и медиа-ресурсы:
  * `/greed/` — Грех Алчности (Мини-игра "Слоты"):
    * `greed.js` — Логика слотов, анимация рычага, вращение барабанов, частицы победы.
    * `greed.css` — Стили оформления автомата и его адаптивная вёрстка.
  * *(Сюда будут добавляться аналогичные папки для остальных грехов, например: `/pride/`, `/wrath/` и т.д.)*

## 📱 Как играть с телефона (актуальная сборка)

Игра выложена на GitHub Pages: **https://porcuvermis.github.io/Svinocherv-Tamagochi/**
В Safari эту ссылку можно добавить на домашний экран и запускать как обычное
приложение (полный экран, работает без сети).

**Иконка всегда открывает ветку, в которую коммитили последней.** Запушили —
через минуту тапнули иконку и смотрят правку. Мержить в `main` ради этого не
нужно: мерж означает «принято», а не «покажи».

Список всех сборок, если надо вернуться к конкретной ветке:
**https://porcuvermis.github.io/Svinocherv-Tamagochi/preview/**

Важно для правок: **номера версий `?v=...` в `index.html` вручную поднимать
не нужно** — при деплое всем ассетам проставляется общий номер сборки, так
что закешированного старого кода на телефоне не остаётся.

Подробности, проверка версии и аварийная очистка кеша — `docs/deploy-iphone.md`.

## 🤖 Инструкция для ИИ (AI Prompt Integration)
> **Уважаемый ИИ!** Этот блок написан для чат-ассистента, которому файлы
> присылают в переписке. Если у тебя есть доступ к репозиторию — правила 1 и 2
> к тебе не относятся: правь точечно, а не переписывай файлы целиком. Правила
> 3–6 в силе всегда.
>
> Этот проект полностью загружен в текущую сессию. Тебе доступны все файлы кода.
>
> ### 🛑 Правила выдачи кода и изменений (Критически важно!):
> 1. **Пиши измененные файлы ЦЕЛИКОМ:** Если в файле происходят изменения (добавление логики, рефакторинг, исправление багов), ты **обязан предоставить полный, обновленный код этого файла** в одном блоке кода. Никаких урезанных кусков, пропусков `// ... остальной код ...` или заглушек. Пользователь должен иметь возможность просто скопировать твой код и полностью заменить им содержимое файла.
> 2. **Исключение для точечных правок:** Если нужно изменить буквально одну строку, убрать запятую или добавить одно свойство, ты можешь не писать весь файл целиком, **НО** ты обязан предоставить наглядное сравнение в формате "Было / Стало":
>    * **Было:** Показать кусок оригинального кода с контекстом (2-3 строки до и после).
>    * **Стало:** Показать измененный кусок кода с тем же контекстом, чтобы было предельно ясно, куда именно вносить правку.
> 3. **Придерживайся дизайн-концепции:** Не предлагай громоздких кнопок интерфейса "Закрыть" или "Крутить". Интерфейс должен быть максимально чистым, графическим и интуитивным (клики по самому Canvas, графические крестики для выхода).
> 4. **Изучай контекст самостоятельно:** Самостоятельно анализируй структуру, методы связки ядра игры (`main.js`) с модулями мини-игр и текущую верстку. Способы вызова меню и анимации могут меняться — опирайся только на актуальный код в файлах.
> 5. **Соблюдай модульность:** При написании новых фич или добавлении мини-игр строго следуй архитектуре проекта. Новые игры складывай в отдельные папки внутри `/src/minigames/`.
> 6. **Действуй точечно:** Не трать контекст на пересказ очевидных вещей и структуры игры. Сразу переходи к решению **конкретной актуальной проблемы**, описанной пользователем в текущем запросе.
