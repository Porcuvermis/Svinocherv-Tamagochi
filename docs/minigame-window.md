# Окно мини-игры: один шаблон на семь грехов

Файлы: `src/core/minigame-window.css` (вид) и `src/core/minigame-window.js`
(сборка). Пример применения — гнев: `src/minigames/wrath/`.

> **Куда идёт окно.** Вопрос «выйти?» и плоская рамка цветом греха — нынешнее
> состояние, не цель. Цель для всех семи игр: рамка из материала греха (она
> же переход), крестик из элементов рамки, выход без диалога несколькими
> нажатиями. Первая — похоть: `docs/plan/25-lust-foam-transition.md`. Игры
> без шкурки пока живут по правилам ниже.

## Правило

**Мини-игра не рисует своё окно.** Она отдаёт содержимое, а рамку, шапку с
названием греха, крестик и вопрос «выйти?» надевает общая сборка. Одинаково
у всех, всегда:

* окно **во весь экран** (весь холст 390×844, а не карточка посередине);
* **рамка по краю холста** — цветом греха, без отступа и без скруглений.
  Отступ был 10px, и в этой щели по всему периметру просвечивала комната:
  игрок видел под мини-игрой чужой экран, а браузер каждый кадр его рисовал;
* **крестик** в правом верхнем углу шапки, в одном и том же месте у всех игр;
* **вопрос при выходе** — «Выйти из мини-игры? Прогресс не сохранится.» с
  кнопками «Остаться» / «Выйти». Игра может разрешить выход без вопроса там,
  где терять уже нечего (`canLeave`).

## Зачем

Окна писались по одному и разошлись. У зависти крестик справа сверху и
вопрос при выходе, у гнева — крестик посередине между полосками здоровья и
выход без вопроса, у лени своя карточка, у алчности своя. Игрок при этом
видит не семь игр, а одну игру с семью экранами: и каждый раз заново ищет,
где закрывать и спросят ли его.

Скопировать разметку «как у соседа» дешевле, чем сделать правильно, поэтому
правильное должно происходить само. Отсюда сборка, а не соглашение о
классах: забыть крестик или переписать вопрос своими словами больше нельзя.

## Как подключается

В `index.html` у экрана лежит только содержимое игры:

```html
<div id="wrath-game" class="minigame-screen mg-window" data-sin="wrath">
    ... то, что у этой игры своё ...
</div>
```

В `init()` мини-игры — до поиска остальных элементов, потому что сборка
переносит содержимое внутрь рамки:

```js
this.win = MinigameWindow.attach(this.screenElement, {
    sin: 'wrath',                    // цвет и название берутся из ECONOMY
    onLeave: () => this.close(),     // что делать, когда игрок решил выйти
    canLeave: () => this.fightOver   // когда спрашивать не о чем
});
```

Дальше игре доступны `this.win.hideConfirm()`, `showConfirm()`,
`isConfirmOpen()` (пригодится, чтобы не ловить тапы по полю, пока висит
вопрос) и `setTitle()`.

Закрытие: `MinigameWindow.restoreHud()` ничего не делает и оставлен пустым.
Раньше он возвращал верхний HUD со шкалами (те же семь строк были скопированы
в `close()` каждой игры), но HUD снят целиком: грехи живут в своём меню
(`docs/sins-menu.md`), и возвращать после мини-игры нечего.

**Комната под окном гасится дважды, и оба раза нужны.**

1. *Анимация.* Персонаж главного экрана не знает, что его накрыли, и
   продолжает считать кадры — рендерер такое не ловит, сцена по всем
   признакам видима. На медленном телефоне это стоило одиннадцати кадров в
   бою гнева. Останавливает `MinigameWindow.pauseRoom()` / `resumeRoom()`, и
   то же самое делает наблюдатель в `main.js` для игр на своих окнах.
2. *Отрисовка.* Остановленная сцена всё равно КРАСИТСЯ: семьсот узлов
   персонажа, локация, кошелёк. Снимается классом `mg-open` на
   `#game-container` (вешает тот же наблюдатель в `main.js`), а правило в
   `style.css` прячет всё, кроме самих мини-игр и кнопки 🐞.

Прячется именно `visibility: hidden`, а не `display: none`: раскладка комнаты
меряется по-настоящему (позиция червя, границы пола), и обнулять замеры на
каждый заход в мини-игру значит собирать сцену заново на выходе. Так же
ничего не выгружается — возврат мгновенный.

## Шкурка и покров (цель для всех семи)

Опция `skin` у `attach()` надевает рамку из материала греха вместо плоской
полоски цветом греха (первая — пена ванной, `src/minigames/lust/lust-foam.js`):

* `rim { side, top }` — толщина боков и верха; низ выходит сам. Тело окна
  уменьшается `translate + scale(k)` во внутренний прямоугольник
  (`MinigameWindow.skinGeometry`), раскладка игры внутри прежняя.
* `cross { x, y, size }` — где крестик нарисован рамкой; кнопка `.mg-close`
  становится невидимой зоной нажатия над ним.
* `drawGen(ctx, scale)` (или `draw`) — рисунок рамки. Окно гонит его кусками
  в простое через `SKIN_DELAY` после сборки (`ensureSkin()` при входе
  дорисует остаток) и выводит на экран **четырьмя полосами** шириной
  `reach()`, а не холстом во весь экран.
* `bg` — фон окна под рамкой.
* `prepareGen(scale)` — всё, что нужно переходу (у пены — грозди, атлас,
  неподвижная пена), в той же задаче простоя следом за рамкой; затем окно
  зовёт `MgVeil.prewarm` → `skin.veilWarm(ctx)`: картинки один раз рисуются,
  чтобы их загрузка в видеокарту случилась не в миг нажатия.
* Переход для покрова (`src/core/mg-veil.js`): `VEIL_MS[mode]`,
  `veilStart(ctx, mode)` — начало хода, `veil(ctx, mode, p, scale, fx)` —
  кадр (холст покрова между кадрами не чистится, `fx` — чистится),
  `veilStill(ctx)` — покров стоит, пока игра дозревает (полное разрешение),
  `veilPending()` — ход ещё не дорисован (держит ход дольше времени),
  `veilOpacity(mode, p)` — прозрачность покрова целиком. Ходы: `cover` /
  `reveal` на входе, `close` / `clear` на выходе, `burst` / `pop` / `finish`
  — нажатия в забеге. Готовность игры — `minigame.veilReady()`; колесо
  грехов закрывается уже под сплошным покровом (`enter(minigame,
  beforeOpen)`).

Выход посреди забега у окна со шкуркой — без вопроса: `requestClose()`
отдаёт нажатие покрову (`MgVeil.knock`), три нажатия подряд, каждое
бросает на экран материал (ходы `burst` / `pop` / `finish` у шкурки).
Вопрос «выйти?» остаётся окнам без шкурки и прогонам без покрова.

Чего у шкурки быть не должно: css-фильтров на холсте рамки (пересчитываются
каждый кадр — `docs/traps.md`, п. 164), холста во весь экран, материала одной
картинкой (кусок из неё целым не убрать — п. 165), щелей в залитом покрове
(п. 166) и полного разрешения покрова в движении (п. 167).

## Что настраивает сама игра

Только переменными, не переопределением правил:

| Переменная | Что это | Откуда берётся |
|---|---|---|
| `--mg-accent` | цвет рамки, названия, кнопки «остаться» | `ECONOMY.sins[грех].color`, ставит сборка |
| `--mg-bg` | фон под содержимым | css мини-игры |
| `--mg-inset` | отступ рамки от края холста | по умолчанию 0: рамка идёт по краю |

Пример (`wrath.css`):

```css
#wrath-game {
    --mg-bg:
        radial-gradient(ellipse at 15% 40%, rgba(255, 105, 160, 0.18), transparent 55%),
        #170606;
}
```

Порядок подключения важен: `minigame-window.css` идёт **до** стилей
мини-игр, `minigame-window.js` — **до** их скриптов.

## Раскладка внутри

Содержимое живёт в `.mg-body` — это остаток высоты под шапкой, с
`overflow: hidden`. Всё, что игра позиционирует абсолютно, отсчитывается от
него.

Важное следствие для рисования: **окно теперь у всех игр одного размера и
почти во весь экран**, а раньше каждая карточка была своей. Всё, что
считалось от размера холста, надо проверять на вписывание по ОБЕИМ сторонам.
В гневе на этом сразу вылезли обрезанные морды: масштаб бойца считался
только от высоты и был подобран под старую карточку 400×700. Кончилось это
тем, что своё рисование в гневе выкинули совсем, а общая модель вписывается
в отведённое место по ИЗМЕРЕННОМУ силуэту (`WrathFighter.fitWorm`) — тогда
ни форма окна, ни будущее взросление червя раскладку не ломают.
