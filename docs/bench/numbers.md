# Верстак: числа

Цены, награды, скорости шкал, ступени прокачки, вероятности. Всё, что можно
посчитать до того, как рисовать.

---

## Где что лежит

| | |
|---|---|
| **все числа баланса** | `src/config/economy.js` |
| снаряжение гнева | `src/config/wrath-gear.js` |
| гардероб тщеславия | `src/config/pride-wardrobe.js` |
| кухня: ингредиенты, качество блюда | `src/config/kitchen.js` |
| сад: виды, ступени, времена | `src/config/garden.js` |
| **единственное место начисления** | `src/core/backend.js` |
| замысел прогрессии | `docs/plan/15-progression.md` |

Конфиг потом переезжает на сервер **как есть**, поэтому в нём нет ни одной
функции — только данные.

---

## 1. Крепёж: числа не живут в коде

Инвариант 3: числа баланса живут в конфиге, а не в мини-играх. Новая
механика = новая запись в таблице, а не новая константа рядом с кодом
экрана.

---

## 2. Правило первое: сначала посчитать, потом добавлять контент

**Три бесполезные или непроходимые механики были пойманы калькулятором за
минуту и ни одна — чтением кода.** Симулятор пишется раньше содержимого.

| инструмент | на какой вопрос отвечает |
|---|---|
| `tools/progression.js` | сколько времени занимает путь по живому конфигу |
| `tools/sim-progression.js` | **календарь ПО ВСЕЙ ИГРЕ: за сколько выкупается всё и как часто игрок что-то покупает** |
| `tools/sim-slots.js` | автомат алчности: веса, выплаты, возврат |
| `tools/sim-rogue.js` | забег: доходимость по сложностям, не обязателен ли какой-то путь |
| `tools/sim-wrath-year.js` | за сколько дней выкупается всё содержимое гнева |
| `tools/sim-wrath-foe.js` | ровен ли соперник и двигает ли снаряжение шанс победы |
| `tools/sim-wrath-regen.js` | темп боёв: что выходит за час и за сутки |
| `tools/sim-garden.js`, `tools/sim-pride.js`, `tools/sim-lust.js` | то же для своих грехов |
| `tools/measure-power.js` | сила сборки |

Все они считают **по живому конфигу**: поменял число — прогнал симулятор.
Браузер не нужен, секунды.

---

## 3. Что обязан помнить автор

1. **Баланс меряется ВДОЛЬ ПУТИ прокачки, а не по крайним сборкам.**
   Середина пути — то место, где механика обычно и ломается.
2. **Развилка, где один путь лучше остальных, — это не выбор, а
   обязанность.** Симулятор обязан проверять, что ни один путь не
   обязателен.
3. **Убывающая доходность, в хвосте которой всё становится единицей,** —
   это конец интереса, а не мягкая посадка.
4. **Два тормоза на одной механике — это не темп, а тупик.**
5. **Правило игры поменялось — цены не подвинулись, а пересчитались.**
   Ручная подгонка одного числа под новое правило разъезжается на второй
   правке.
6. **Модель, в которой механику нечем выразить, врёт уверенно.** Если
   симулятор не умеет описать то, что делает игрок, его ответ бесполезен.
7. **Лестницу растягивают КОЛИЧЕСТВОМ ступеней, а не ценой.** Полная
   прокачка — полгода-год, покупка — раз в неделю; эти два требования
   совместимы только при мелком шаге. Шесть ступеней, растянутые на полгода,
   означают месяц тишины перед последней, и в этой тишине игрок уходит
   (`docs/plan/15-progression.md`, разд. 4а).
8. **Провалившаяся проверка — сначала повод спросить, ТУ ЛИ величину она
   меряет.** Дважды подряд здесь падала верная проверка неверного вопроса:
   «жетон дороже суток дохода» (темп держит голод, а не цена) и «худший
   промежуток между покупками» (последняя ступень самая дорогая по
   построению). Подгонка числа под неверный вопрос даёт зелёный прогон и
   кривую экономику.

---

## 4. Как проверить

```bash
NODE_PATH=/opt/node22/lib/node_modules node tools/progression.js
NODE_PATH=/opt/node22/lib/node_modules node tools/sim-<что>.js
```

Отмотка времени в игре — кнопка 🐞: отматываются не системные часы, а метки
в состоянии, то есть проверяется ровно тот механизм, что работает в игре.
