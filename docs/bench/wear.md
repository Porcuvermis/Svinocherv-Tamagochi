# Верстак: одежда на черве

**Здесь всё, что нужно, чтобы сделать новую вещь. Больше ничего открывать не
надо.** Технику придумывать не надо тоже — она уже отлита: крепёж один,
размерность одна, поведение при развороте одно. Новая вещь — это новая
отливка в ту же форму: меняется силуэт и цвет, крепления те же.

## 1. Крепёж: семь гнёзд, других нет

| гнездо | где сидит | что туда |
|---|---|---|
| `hat` | макушка | цилиндры, шляпы, кепки |
| `eyes` | глаза | очки, повязка на глаз, монокль |
| `mouth` | рот | сигара, соска, маска |
| `ears` | уши (**оба сразу**) | серьги, клипсы |
| `neck` | первый сегмент после головы | воротники, цепи, шарфы |
| `coat` | **два соседних сегмента** | пиджаки, фраки, куртки, кофты |
| `tailTip` | кончик хвоста | носки, чулки, ботинки, банты |

Гнездо выбирает **ЧАСТЬ**, а не точку на ней, и вещь сидит по центру части.
Смещать её вдоль оси нельзя: у отметины разброс — свойство, у одежды — съезд.
Единственное исключение объявляет само гнездо: у `tailTip` место — кончик, а
не середина.

Части берутся **по роли**, а не по номеру (`first` / `last-1` / `last`):
число сегментов меняется при взрослении, а «первый после головы» и
«последний» остаются собой.

### Посадка — свойство ГНЕЗДА, а не предмета

`seat` объявлен у гнезда: любые очки садятся на глаза, любая сигара — на рот.
Предмету остаётся только картинка.

| `seat` | как считается |
|---|---|
| `crown` | формула макушки: слегка ведёт за лицом |
| `eyes` | **каждый кусок с `data-eye` садится на СВОЙ глаз**, а `data-span` растягивается между ними. Одним узлом на оба глаза не выходит: при повороте они сужаются по-разному |
| `mouth` | повторяет transform РТА; рисуется в местных координатах рта |
| `ears` | повторяет transform СВОЕГО уха; вещь рисуется один раз, левая сторона — отражением |
| `axis` | на оси части (всё, что на теле) |

### Верхняя одежда занимает ДВА сегмента

Пиджак, фрак, куртка, кофта рисуются **двумя половинами** — верхом и низом:

```js
'моя-куртка': { kind: 'cloth', parts: { upper: {…}, lower: {…} } }
```

Для игрока это одна вещь: сегменты перекрываются, половины стоят вплотную,
шва не видно. Раньше такая вещь жила на одном животе, и костюм читался
разорванным — воротник на шее, пиджак на животе, между ними голое тело.

**Половины меряются ОБЩЕЙ единицей, а не своей долей.** Сегменты разной
толщины, и одна и та же доля даёт в них разную ширину — манишка сверху
оказывалась шире, чем снизу, и вещь разваливалась ровно по шву. Для этого
есть `g.uOf(v, k)`: `k` — ширина в общих единицах вещи.

**Кромка, которой половины стыкуются, не обводится:** `seam: 'top'` у нижней,
`seam: 'bottom'` у верхней. Это не край вещи, а её середина; пока её
обводили, поперёк фрака шла чернильная линия и он читался двумя надетыми
друг на друга кусками.

**Лицо половин выстраивается по оси ОПОРНОЙ части** (последней в списке).
Сегменты не стоят на одной вертикали, и манишка, отцентрованная по каждому
своему, шла по шву зигзагом. Обшивка при этом обнимает СВОЙ сегмент — ей это
смещение не нужно и вредно.

Украшение поверх (лента) может занимать ОДНУ половину: `parts: { lower: {…} }`.
Верхняя одежда — обязана обе.

Узел вещи живёт в слое **над кожей** (`worm-wear-layer`) и повторяет
`transform` своей части. Про ходьбу, камеру и изгиб тела вещи знать не надо.

## 2. Размерность: сетка (u, v)

Единственная система координат, в которой разрешено рисовать одежду.

```
u   поперёк тела:  0 — середина,  ±1 — РОВНО край части на этой высоте
v   вдоль охвата:  0 — верхняя кромка вещи,  1 — нижняя
```

`cover: [сверху, снизу]` — охват в долях полувысоты части (−1 макушка,
+1 низ). Он и задаёт форму: охват, начатый выше середины части, сам даёт
плечи у́же подола — это профиль сегмента, а не подобранная трапеция.

Инструменты (`g` — контекст выкройки):

| | |
|---|---|
| `g.at(u, v)` → `{x, y}` | точка выкройки |
| `g.p(u, v)` | она же строкой для пути |
| `g.d([[u,v], …])` | замкнутый путь; участок по краю идёт ДУГОЙ по телу |
| `g.band(v0, v1)` | полоса во всю ширину тела |
| `g.hw(v)`, `g.y(v)` | полуширина тела и высота на этой доле охвата |
| `g.out/po(u, v, dy)` | точка НИЖЕ выкройки — только для подола |
| `g.swing(k, svg, pivot)` | качающийся кусок; `pivot` — точка крепления |
| `g.C`, `g.ink`, `g.rx`, `g.ry`, `g.eye` | палитра, чернила, габариты, глаз |

**В записи вещи не должно быть ни одного `rx * 0.46`.** Как только оно
появляется — вещь перестала быть привязанной к телу и поехала. Это не
стилистика: ровно так восемь вещей разъехались по-разному, и фрак стал похож
на галстук-бабочку.

Длинная часть (хвост) — не шар: у неё габарит по длине и по толщине разные.
Вещь на неё просит `along: true`, и тогда `u` бежит ВДОЛЬ части.

## 3. Два рода вещей

**`cloth`** — ткань, скроенная по телу: фрак, лента, воротник, гетра.
Объявляет `cover`, рисуется в (u, v).

**`rigid`** — твёрдый предмет, который не кроится, а надевается: очки,
цилиндр, цепь, бант. Объявляет `halfW` и опору `seat`:

| `seat` | |
|---|---|
| `face` | лежит на лице и едет вместе с чертами (очки) |
| `crown` | надет на череп сверху, лишь слегка ведёт за лицом (цилиндр) |
| `axis` | на оси части, поворот головы его не касается |

## 4. Три слоя вещи: обшивка, лицо, подол

Это главное, что надо понять про одежду. Вещь — **не плоская картинка на
теле**, а три разных слоя, которые по-разному ведут себя при развороте.

| слой | что это | что с ним на развороте |
|---|---|---|
| **обшивка** | ткань, обнимающая часть кругом: `base`, `cut`, кромка, `paint` | **ничего.** Она идёт вокруг части и при ЛЮБОМ ракурсе достаёт до обоих краёв силуэта — как рукав на руке |
| **лицо** | то, что нарисовано на груди: `face`, `over` — манишка, лацканы, пуговица, бант, медаль | сужается и съезжает вбок: уходит на дальний бок и почти пропадает |
| **подол** | `hang` — фалды, ленты, подвески | качается от ходьбы и наклона телефона, ВОКРУГ своей точки крепления (`pivot`) |

**Зачем это разделение.** Пока ракурс сужал ВСЮ вещь, она на развороте
скукоживалась к центру: по бокам вылезала голая кожа там, где ткань обязана
быть, и игрок видел не «повернулся в пиджаке», а «одежда съёжилась».
Обшивка не сужается именно потому, что она круговая.

Вопрос, который решает, куда класть деталь: **это нарисовано НА ткани или
лежит НА груди?** Полоска вдоль ленты — на ткани (`paint`). Медаль — на
груди (`over`). Манишка — на груди (`face`). Полоски на гетре — на ткани.

## 5. Что станок делает сам — и чего поэтому не надо делать руками

* строит выкройку и кладёт **непрозрачную** основу: тело под тканью не
  просвечивает;
* **обводит вещь ЦЕЛИКОМ, той же линией, что контур персонажа**
  (`STROKE.contour`, чернила). У персонажа контур есть в любом ракурсе — и у
  одежды должен быть всегда. Там, где кромка идёт по силуэту, она ложится НА
  контур тела: та же толщина, тот же цвет, шва не видно. Кромка доходит до
  края части ровно (`HUG = 1`), без полоски голой кожи между тканью и
  контуром;
* **прогибает опоясывающие кромки книзу.** Камера стоит выше червя, и любая
  линия поперёк круглого тела видна дугой. Прямая кромка читается скотчем;
* **разворот: сдвиг вбок и сужение ЛИЦА, а не вращение и не сжатие всей
  вещи.** Для игрока червь стоит вертикально и поворачивается целиком, как
  очки на лице;
* качает всё, что в `hang`, — от скорости ходьбы и от наклона телефона,
  **вокруг объявленной точки крепления** и с поправкой на зеркало и на угол
  носителя (см. ниже);
* считает полуширину вещи: у ткани она равна единице по построению.

## 6. Что обязан сделать художник

1. **Светлое поле.** Кожа у червя бывает почти чёрной, и тёмная вещь на ней
   не видна ни в каком ракурсе. По светлому наряд и опознают.
2. **Не больше трёх читаемых фигур.** Вещь размером с монету; четвёртая
   фигура превращает её в кашу.
3. **Вещь обязана читаться ужатой до 0.62 своей ширины** — столько от неё
   остаётся при полном развороте. Значит ни одной важной детали у́же шестой
   части сегмента: на развороте её не станет.
4. **Всё, что свисает, — только через `hang`.** Это единственное место, где
   разрешено выйти за тело, и единственное, что качается. Качается оно
   ВЕЗДЕ — и на теле, и на голове: список подвижных деталей общий.
5. **Если подвеска пришита не к началу координат части — объяви `pivot`.**
   `pivot: g => ({x, y})` в тех же местных координатах, в которых нарисована
   подвеска. Без этого поворот идёт вокруг начала координат носителя, и
   подвеска уезжает со своего крепления по дуге: серьга, висящая на мочке в
   двух десятках единиц от корня уха, при наклоне телефона просто улетала
   в воздух (`docs/traps.md`, п. 126). Умолчание — начало координат: фалды
   с `pivot` на подоле, бант — на узле, серьга — на гвоздике, подвеска
   цепочки — на нижнем звене.
6. **Полосы и вставки не доводятся до `u = ±1`.** На краю станок ведёт
   кромку дугой по контуру части, и полоса «от 0.8 до 1» захватывает весь
   конец выкройки серпом: у носка на хвосте так вышло тёмное кольцо со
   светлой серединой вместо полосатого носка.
7. **Опорные точки — только `g.at`.** См. пункт про `rx * 0.46`.

## 7. Шаблон новой вещи

Скопировать в `WormCosmetics.ITEMS`, поменять цвета и точки. Технических
решений здесь принимать нечего — всё уже принято.

```js
// Ткань, скроенная по телу.
'моя-вещь': {
    kind: 'cloth',
    cover: [-0.74, 0.36],          // докуда по части идёт ткань
    base: g => g.C.cloth[500],     // цвет основы
    // Необязательно: своя форма выкройки. Без неё — полоса во всю часть.
    // cut: g => [[-1, 0], [1, 0], [1, 1], [-1, 1]],
    // Рисунок НА ткани — едет с обшивкой, ракурсу не подчиняется.
    // paint: g => `<path d="${g.band(0.3, 0.45)}" fill="${g.C.gold[500]}"/>`,
    // Лицевая сторона — то, что на груди. Сужается и съезжает при развороте.
    faceHalf: 0.6,
    face: g => `<path d="${g.d([[-0.58, 0.02], [0.58, 0.02], [0, 0.78]])}"
                  fill="${g.C.linen[300]}"/>`,
    // Необязательно: свисающее. Качает его станок.
    // hang: g => `<path d="M ${g.po(-0.9, 1, 0)} L ${g.po(0.9, 1, 0)}
    //                      L ${g.po(0, 1, 0.8)} Z" fill="${g.C.cloth[900]}"/>`,
    // Необязательно: поверх обводки — золото, пуговицы, застёжка.
    // Это тоже ЛИЦО: съезжает вместе с ним.
    // over: g => ``
},

// Твёрдая вещь: не кроится, а надевается на опору.
'мой-предмет': {
    kind: 'rigid', seat: 'axis', halfW: 0.9,
    draw: g => `<circle cx="${g.at(0, 0.5).x}" cy="${g.at(0, 0.5).y}"
                  r="${Math.min(g.rx, g.ry) * 0.3}" fill="${g.C.gold[500]}"/>`
},
```

Верхняя одежда — двумя половинами:

```js
'моя-куртка': {
    kind: 'cloth',
    parts: {
        upper: { cover: [-0.80, 0.78], base: g => g.C.cloth[500],
                 faceHalf: 0.6, face: g => `…` },
        lower: { cover: [-0.92, 0.10], base: g => g.C.cloth[500],
                 faceHalf: 0.55, face: g => `…`, hang: g => `…` }
    }
},
```

И строка в каталоге `src/config/pride-wardrobe.js`:

```js
{ id: 'моя-вещь', slot: 'body', kind: 'wear', price: { pride_kiss: 500 }, sits: 0.93 },
```

`sits` — какая доля вещи обязана лежать на теле. Это свойство КРОЯ, а не
подгонка: у банта петли законно выходят за хвост, у цилиндра поля — за череп.

**У вещей на морде и на ушах `sits` равен нулю, и это правильно.** Доля
меряется по силуэтам ЧАСТЕЙ ТЕЛА, а морда и уши в них не входят — это черты,
а не части. Требовать от серьги «лежать на теле» значит требовать, чтобы она
уехала с уха на череп. За такие вещи отвечают другие проверки: «едет вместе
со своей чертой» и «держится лица при любом повороте».

### Вещь на паре черт

Очки, серьги — и будущая повязка на один глаз. Кусок помечается тем, на чём
сидит, и садится туда сам:

| пометка | что делает станок |
|---|---|
| `data-eye="left"` / `"right"` | кусок повторяет transform своего глаза |
| `data-span="1"` | растягивается между глазами (рисуется шириной РОВНО 1, центр в нуле) |
| `data-side` у ушей | вещь рисуется ОДИН раз, для правой стороны; левая — отражением |

**Витрина не умеет ничего из этого**: там нет ни тела, ни рендерера. Поэтому
у гнёзд с чертами есть раскладка по умолчанию — `WormCosmetics.CARD`, по
одной короткой записи на гнездо. Отдельной картинки для карточки не заводить:
она разойдётся с настоящей вещью на первой же правке.

## 7а. Висящее и наклон телефона

Подвеска обязана искать низ **экрана**, а не низ своего носителя. Рендерер
считает её угол пружиной (ход червя + наклон телефона) в понятиях игрока —
«куда уехал свободный конец, плюс вправо», — и в дерево пишет:

```
θ = flip · (−ang − угол носителя)
```

Три множителя, и каждый появился из своего дефекта:

| что | зачем | где живёт |
|---|---|---|
| `pivot` | подвеска вертится вокруг СВОЕГО крепления, а не вокруг начала координат носителя | объявляет вещь (`pattern.pivot`) |
| угол носителя | ухо наклонено, хвост изогнут — висящее это вычитает, иначе висит «вниз по уху» | ухо: живой `baseAngle`; хвост: `state.tailWearRot` |
| `flip` | левая копия парной вещи живёт внутри `scale(-1,1)`, там поворот виден наоборот | место монтажа — оно же копию и отражало |

Минус перед `ang` — потому что у svg ось Y вниз и положительный поворот
уводит висящий конец ВЛЕВО (`docs/traps.md`, п. 116). Он ставится ОДИН раз,
здесь, и больше нигде о знаке думать не надо.

## 8. Как проверить

```bash
python3 -m http.server 8777            # один раз на сессию
NODE_PATH=/opt/node22/lib/node_modules node tools/test-wardrobe.js
```

```bash
NODE_PATH=/opt/node22/lib/node_modules node tools/test-tilt.js
```

`test-wardrobe` стережёт: у вещи есть выкройка и объявлен род; у ткани объявлен охват и она
доходит до краёв части; вещь лежит на теле не меньше заявленного при пяти
ракурсах; у висящего пришитый конец на теле; надетое на голову едет с лицом;
линзы на яблоках; живот не затянут целиком; тело поворачивается, а не
крутится; хвост гнётся вместе с надетым; висящее висит вниз по экрану,
качается на ходу и слушается наклона.

`test-tilt` стережёт качание **как механизм**, а не как свойство одной вещи:
он берёт КАЖДЫЙ узел `[data-swing]`, какой есть на червя, и спрашивает с него
четыре вещи — точка крепления стоит на месте при любом угле; точка крепления
лежит НА подвеске; свободный конец ниже крепления по экрану; завал телефона
вправо уводит конец вправо, у каждой копии отдельно. Мерится средним по
сотне кадров: ход червя качает висящее сильнее наклона, но за сотню кадров
даёт около нуля.

Отдельный прогон появился потому, что проверка внутри `test-wardrobe`
измеряла ОДНУ вещь одним числом и была зелена при обоих дефектах серёг
(`docs/traps.md`, п. 128).
