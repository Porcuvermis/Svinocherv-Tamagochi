# Верстак: новая мини-игра или новый экран

Семь грехов — семь мини-игр. Общего у них больше, чем кажется: окно, способ
сказать «я закончилась», способ получить награду и запрет на слова.

---

## Где что лежит

| | |
|---|---|
| **общее окно** | `src/core/minigame-window.js` |
| **шина событий** | `src/core/events.js` |
| **единственное место, где что-то начисляется** | `src/core/backend.js` |
| состояние игрока | `src/core/state.js` |
| маршрутизация по экранам | `main.js` |
| колесо грехов (откуда игру открывают) | `src/core/sins-menu.js` |
| отдача в палец | `src/core/haptics.js` |
| прилёт/улёт в кошельке | `src/core/wallet-fx.js` |
| замысел конкретного греха | `docs/plan/` по названию |
| разбор окна | `docs/minigame-window.md` |

## 1. Крепёж: своя папка и общее окно

Новая мини-игра — **отдельная папка** `src/minigames/<грех>/`, а не дописка
в существующие файлы. Внутри — js и css.

Окно она себе НЕ рисует: вешает `MinigameWindow.attach()` и кладёт внутрь
только содержимое. Рамка, шапка, крестик и вопрос «выйти?» — общие на все
семь, и все семь открываются на весь экран (инвариант 8). Своя карточка,
свой крестик, выход без вопроса — так нельзя.

Одна игра из семи (зависть) ещё живёт на собственном окне. Это **долг, а не
образец**.

## 2. Размерность: кто кому что должен

```
мини-игра  →  бросает событие с результатом { sin, mode, outcome, meta }
конфиг наград  →  решает, что за это дать
Backend  →  единственный, кто начисляет
```

**Мини-игра ничего не начисляет** (инвариант 2). Записи вида
`GameManager.sins.X.value = 100` запрещены. **Числа баланса живут в конфиге**
(инвариант 3) — см. [`numbers.md`](numbers.md).

**Никаких тикающих таймеров состояния** (инвариант 1): значение шкалы,
оффлайн-доход, кулдаун считаются формулой от метки времени. Таймеры на
клиенте — только для картинки.

---

## 3. Что движок делает сам

* окно, крестик, вопрос при выходе, гашение комнаты под открытой игрой;
* показ траты и начисления: цифра вылетает из счётчика валюты сама
  (`WalletFx` подписан на `GameState.addCurrency`). Строк «−1 жетон» на
  экранах заводить не надо;
* отдача в палец: `Haptics` сам решает, Telegram это, `vibrate` или тишина;
* узел греха в колесе горит, когда за заход заплатят. **Чем это меряется —
  дело каждого греха** (`SinsMenu.readers`), общего правила «по половине
  шкалы» нет и заводить его не надо.

---

## 4. Что обязан сделать автор

1. **Ни одного слова.** Иконки, цвет, движение и числа. Цифра — не слово.
   Не игра и под правило не попадает: debug-панели, заголовок вкладки,
   манифест. Словарь замен — `docs/plan/11-no-words.md`.
2. **Интерфейс диегетический, где можно.** Предметы, а не меню: у кухни
   холодильник и нож, а не список действий.
3. **Игра обязана открываться без Telegram** (инвариант 7). Нет `initData` —
   локальный игрок, и это штатный режим разработки.
4. **Закрытая мини-игра ничего не крутит.** Анимации и циклы кадров
   выключаются при закрытии, иначе они стоят кадров всю оставшуюся сессию.
5. Если предмет меряется часами или месяцами — своя debug-панель. Иначе
   механику нельзя увидеть вживую (примеры: кухня, сад, тщеславие).

## 5. Шаблон

```
src/minigames/<грех>/
  <грех>.js     экран: MinigameWindow.attach(), содержимое, закрытие
  <грех>.css    стили этого экрана
  <грех>-art.js картинка отдельно от игрового слоя, если её много
```

Подключение в `index.html` идёт ПОСЛЕ ядра: конфиг → события → время →
состояние → переходник → `main.js` → мини-игры.

---

## 6. Как проверить

```bash
NODE_PATH=/opt/node22/lib/node_modules node tools/test-no-words.js    # инвариант 9
NODE_PATH=/opt/node22/lib/node_modules node tools/test-sins-menu.js   # вход из колеса
NODE_PATH=/opt/node22/lib/node_modules node tools/test-<грех>.js      # сама игра
```

Прогоны **водят пальцем по координатам**, а не жмут селекторы: это заодно
проверка, что перевод «экран → сцена» не врёт.
