## 0. Главный вывод

**Половина нужного уже есть, и она бесплатна.** Проверено замером:

| факт | значение |
|---|---|
| узлов в персонаже | **655** |
| из них именованных (`data-*` или `worm-` класс) | **111** (17%) |
| значений `data-part` в живом дереве | **27** (в исходниках видно 13) |
| `document.elementsFromPoint` отдаёт стопку слоёв | **да, уже сейчас** |
| глубина стопки на голове / хвосте | 9 / 8 слоёв |

То есть **«выбрать элемент кистью с циклическим перебором слоёв» работает
без единой правки рендерера.** Браузер уже отдаёт весь стек под пальцем,
а `closest('[data-part]')` уже поднимает от фигуры к части тела.

Но есть три конкретные поломки, которые надо чинить — и все три чинятся
**таблицей имён**, а не переписыванием:

1. `closest('[data-part]')` находит **технические обёртки**, а не части
   тела. Тык в голову возвращает `head-tilt`, а не `head`. Из 27 значений
   `data-part` примерно **10 — служебные** (`head-tilt`, `head-face`,
   `tail-bend`, `eyes`, `ears`, `gaze-*`, `eyelid-*`, `eyesmile-*`).
2. **83% узлов анонимны.** Крупнейшие гнёзда: 294 фигуры вообще без
   слоя-родителя, 51 в `worm-coat-layer`, 36 в `worm-muscle-layer`,
   21 в `worm-skin-tone`.
3. **«Щека» не является узлом.** И это не недоработка — об этом ниже
   отдельный раздел, потому что он определяет всю архитектуру.

## 1. Три сорта визуальных сущностей — и других нет

Это центральный вывод исследования. Всё, во что можно ткнуть пальцем на
персонаже, относится к одному из трёх сортов, и **обращаться с ними надо
по-разному**.

### Сорт А. Узел — «вещь, которая есть в дереве»

Глаз, бровь, ухо, пятачок, рот, сегмент тела, хвост. У них есть
`data-part`, свой `transform`, своя геометрия.

Живой список (замер): `head`, `segment-1`, `segment-2`, `belly`,
`growing-1`, `growing-2`, `tail`, `ear-left`, `ear-right`, `eye-left`,
`eye-right`, `brow-left`, `brow-right`, `snout`, `mouth`, `jaw`, `muzzle`.

**Левый и правый уже разделены.** Это лучшая новость отчёта: `eye-left`,
`ear-right`, `brow-left` — реальные адресуемые узлы.

**Их можно таскать мышкой.** Позиция выражена числами модели
(`eyes.left.offsetX/offsetY`, `ears.left.rotation`), и обратный перевод
существует.

### Сорт Б. Ориентир кривой — «точка на контуре, которой нет в дереве»

**Щека, скула, висок, лоб, брыло, подбородок.**

Череп рисуется одним `path` из шести кубических кривых — три на половину
(`worm-silhouette.js:46 wormSkullHalf`). «Скула» — это **конечная точка
первой кривой**, на высоте `y = −0.08·ry`, с шириной `cheekWidth`.

```
  свод  →  виски  →  СКУЛЫ        (кривая 1)
  скулы →  брыли  →  морда        (кривая 2)
  морда →  подбородок             (кривая 3)
```

Три следствия, каждое важное:

* **Точка вычислима прямо сейчас.** `wormSkullHalf(cfg, yaw, −1)[0].p` —
  это и есть левая скула в долях радиуса. Умножить на `rx/ry` — и вот её
  экранные координаты. Рисовать ручку инспектора есть где.
* **Но функция не экспортирована.** `WormSilhouette` наружу отдаёт
  `skullPath`, `skullHalfWidth`, `skullPolygon`, `skullContains`,
  `eyePlace`, `wearPlace` — а `skullHalf` **нет**. Это правка в одну
  строку и единственное, что нужно от рендерера для всего инспектора
  формы головы.
* **Половины читают ОДИН конфиг.** `cheekWidth` общий на обе стороны;
  асимметрию даёт только ракурс (множители `up`/`lo` для ближней и
  дальней стороны). Значит **перетаскивание левой скулы сдвинет и
  правую** — если не завести per-side дельты. Это единственное место
  во всём предложении, где нужна настоящая правка модели.

### Сорт В. Слой-эффект — «процедурная масса, у которой нет отдельных частей»

Мышечные тяжи, кольца сегментации, щетина, складки, пятна тона, органы,
блик, матовое пятно, контактная тень.

Это те самые 83% анонимных узлов. И они анонимны **правильно**: они
порождены детерминированным шумом от сида. Отдельный тяж не имеет смысла
— его положение это `anatRng(anatomy, partName, salt)`.

**Их нельзя таскать. Их можно только крутить целиком** — плотность, тон,
видимость, сид. Попытка дать им ручки по штукам была бы худшим решением
во всём проекте.

### Почему это разделение решает задачу

Каждый сорт получает **свой способ управления**, и ни один не притворяется
другим:

| сорт | выбор | редактирование |
|---|---|---|
| **А. Узел** | тык → `closest` → таблица имён | **перетаскивание мышкой** |
| **Б. Ориентир** | ручка на контуре | **перетаскивание ручки** |
| **В. Слой** | кисть с перебором стопки | **ползунок** (плотность/сила) |

## 2. Промежуточный слой сущностей

Один новый файл — назовём `worm-parts.js`. **Чистая таблица, ни строчки
рисования.** Единственный источник ответа на вопрос «как это называется
по-человечески».

### Что в таблице

```
{
  key:      'cheek-left',
  title:    'левая скула',
  kind:     'landmark',              // node | landmark | layer
  find:     …как достать с экрана…,
  at:       …где она сейчас (экранные координаты)…,
  knobs:    ['headWidthCheek', 'headRelief'],
  parent:   'head',
  yawRole:  'surface',               // черта | обшивка | лицо
  note:     'конец первой кривой черепа, высота −0.08·ry'
}
```

Пять полей делают всю работу:

* **`title`** — имя, которое видит человек и получает агент. «Левая
  скула» остаётся «левой скулой» независимо от того, что под ней шесть
  технических слоёв.
* **`kind`** — сорт из раздела 1. Определяет способ редактирования.
* **`at`** — функция, отдающая текущие экранные координаты. Для узла это
  `getBBox` + матрица, для ориентира — `wormSkullHalf`. Из неё рисуются
  ручки и подсветка.
* **`knobs`** — какие ручки словаря (из первого отчёта) на неё влияют.
  Это мост между «ткнул в щёку» и «что крутить».
* **`yawRole`** — тот самый один из трёх способов ответа на ракурс
  (`docs/bench/turn.md`). Нужен и для подсветки в режиме отладки, и
  агенту.

### Список сущностей первой волны

**Голова:** лоб, левый/правый висок, левая/правая скула, левое/правое
брыло, морда, подбородок, пятачок, рот, челюсть, левый/правый глаз,
левое/правое веко, левая/правая бровь, левое/правое ухо.

**Тело:** шея, загривок, живот, растущие сегменты, хвост, кончик хвоста.

**Поверхность:** кожа, блик, матовые участки, кольца, щетина, складки,
поясок, спинной сосуд, контактные тени.

**Нутро:** кишечный тракт, рёбра, органы, сосуды, мышцы.

**Сверху:** шрамы, наряд, слизь.

Порядка **45 сущностей против 655 узлов.** Это и есть масштаб упрощения.

### Почему таблица, а не разметка дерева

Соблазн — расставить `data-name="левая-скула"` по узлам. Так делать
**нельзя** по двум причинам:

1. Щеки в дереве нет и не будет — она точка на кривой.
2. Разметка дерева — это правка десяти файлов стопки и риск сломать
   контракты, на которых держатся семь мини-игр. Таблица снаружи не
   трогает ничего.

## 3. Два режима выбора

### Режим «показать проблему»

Тык в любое место → система **не спрашивает, что ты имел в виду**, а
собирает всё, что видит, и отдаёт агенту.

Что собирается одним кликом:

```
точка:        (x, y) в единицах сцены и в долях части
стопка:       9 слоёв под пальцем, снизу вверх, человеческими именами
сущность:     ближайшая по таблице — «левая скула»
часть:        head  (после фильтрации технических обёрток)
ракурс:       yaw = +0.5, «три четверти вправо»
поза:         стоит, дыхание 0.035, виляние 1.2°
ручки:        какие ручки словаря влияют на эту точку и их значения
снимок:       кадр персонажа + вырез 64×64 вокруг точки
```

Это **ровно то, чего не хватает агенту**: не «персонаж выглядит плоским»,
а «в точке (легко назвать) стопка из девяти слоёв, верхний — блик
`coat.slimeGloss = 0.45`, под ним матовое пятно `coat.matte = 0.35`,
ракурс 0.5, ручка `volume` на 0».

Вся сборка — **чтение DOM и модели**, ни одной правки рендерера.

### Режим «выбрать элемент»

Кисть с циклическим перебором. Механика:

1. Наводишь — подсвечивается **верхний осмысленный** слой, внизу его
   человеческое имя.
2. Колесо / повторный клик — **спускаешься на слой глубже**, подсветка
   переезжает: блик → кожа → мышцы → органы → рёбра → силуэт.
3. Клик — выбрал. Инспектор показывает ручки именно этой сущности.

Стопка берётся из `elementsFromPoint` (проверено: работает), фильтруется
по таблице сущностей, схлопывается — **девять технических слоёв
превращаются в три-четыре осмысленных**.

Подсветка — обводка поверх, **отдельным слоем вне `worm-root`**: фильтр
или лишняя группа на живом слое стоят дорого (`traps.md`, п. 73).

## 4. Инспектор

Открывается на выбранной сущности. Показывает **только те ручки, которые
на неё влияют** — поле `knobs` из таблицы. Четыре группы:

### Размер
Ползунок + число + **ручки прямо на персонаже**. Для узла — габаритная
рамка с углами; для ориентира — точка на контуре. Тянешь — меняется.

### Поворот
Два разных поворота, и их надо различать:
* **ракурс всей фигуры** (`yaw`) — ползунок −1…+1, «отвернулся влево /
  прямо / вправо»;
* **собственный разворот детали** (`ears.left.rotation`, `brow.angle`) —
  дуга-ручка вокруг детали.

Рядом — **подсказка о способе ответа на ракурс**: «эта вещь — черта
поверхности, при повороте уедет к краю и погаснет». Это снимает почти все
жалобы на одежду ещё до того, как они появятся.

### Объём
`volume`, `relief`, `contrast` — и **живая стрелка источника света**
поверх персонажа. Тянешь стрелку — двигается `LIGHT.dirX/dirY` **сразу у
всех частей** (индивидуальные не допускаются — иначе гирлянда из
пластика).

### Освещение
`lightAngle`, `highlight`, `shadow`, `gloss`, `matte`, `verticalFalloff`.

Отдельно — **переключатель «показать только свет»**: убрать цвет, оставить
светлоту. На чёрно-белом персонаже плоскость видно мгновенно, а на
цветном она маскируется тоном. Это самый дешёвый и самый полезный
инструмент во всём инспекторе.

## 5. Прямое редактирование: что обратимо, а что нет

Честная таблица. Тянуть мышкой можно только то, где **существует обратный
перевод** «экранная точка → число модели».

| сущность | тянется? | обратный перевод | цена |
|---|---|---|---|
| **глаз** | ✅ да | экран → локаль головы → `yawAzimuth⁻¹` → `offsetX/offsetY` | 0 |
| **бровь** | ✅ да | смещение + угол | 0 |
| **ухо** | ✅ да | дуга → `rotation`; радиус → `scale` | 0 |
| **пятачок, рот** | ✅ да | Y → доля `ry` (`snoutY`, `mouthY`) | 0 |
| **хвост** | ✅ да | длина/толщина звена | 0 |
| **сегмент тела** | ✅ да | радиус круга цепочки | 0 |
| **скула, висок, лоб, брыло, подбородок** | ⚠️ да, но | нужен экспорт `skullHalf` **и** per-side дельта | малая правка |
| **источник света** | ✅ да | стрелка → `LIGHT.dirX/dirY` | 0 |
| **мышечный тяж, кольцо, щетинка** | ❌ нет | их положение — шум от сида | — |
| **орган по отдельности** | ❌ нет | план зоны строится процедурно | — |
| **отдельный шрам** | ⚠️ частично | `zone` + `t` есть, но размещение само себя валидирует | средняя |

**Главный вывод таблицы: восемь из одиннадцати позиций стоят ноль.**
Обратный перевод уже существует, потому что прямой был написан честно —
через нормализованные доли, а не через пиксели.

### Единственная настоящая правка

Половины черепа читают общий `cheekWidth`. Чтобы левую скулу можно было
тянуть независимо, нужна дельта на сторону:

```
skull: { cheekWidth: 0.97,  cheekWidthL: +0.03 }     // ← новое поле
```

Это **одно поле на ориентир, аддитивно, по умолчанию 0** — старое
поведение сохраняется полностью. Плюс правка `wormSkullHalf`, которая уже
получает `side`.

Риск: асимметричный череп ломает зеркальность, на которую опирается
размещение отметин. Проверяется `test-scars.js` — он и так гоняет шрамы
по реальному контуру.

## 6. Визуальная отладка «что выглядит неправильно»

Принцип: **инструмент показывает не число, а симптом.** Не «matrix 2 7»,
а «эта штука не отвечает на ракурс».

Шесть накладок, каждая отвечает на один вопрос:

| накладка | вопрос | что видно |
|---|---|---|
| **Свет** | почему плоский? | стрелка источника + точки бликов всех частей. Блики не в одну линию = гирлянда |
| **Силуэт** | читается ли форма? | заливка чёрным. Одна вершина на животе или плато из бус |
| **Ракурс** | кто врёт при повороте? | каждая вещь покрашена по своему `yawRole`, ползунок прокручивает yaw |
| **Глубина** | что перед чем? | порядок слоёв по оси, ступеньками |
| **Плотность** | не сыпь ли? | тепловая карта количества деталей на площадь |
| **Цена** | что уронило кадры? | `getFrameStats()` + какая ручка крутилась последней |

Накладка «Ракурс» — самая ценная. Прокрутка `yaw` с подсветкой способа
превращает часовую отладку в секундную: неправильно назначенный способ
видно сразу, потому что вещь красного цвета («черта») ведёт себя как
синяя («обшивка»).

Все шесть — **чтение существующего состояния**. Единственное, чего нет
сегодня, — это ручной прокрутки `yaw`, и она уже есть в API:
`setHeadPose(число)` и `setLivePose({ bodyYaw })`.

## 7. Структурированный контекст для агента

### Что отдаётся

```
ЖАЛОБА      "голова выглядит плоской"

ВЫБРАНО     левая скула (ориентир), внутри: голова
            стопка в точке: блик → кожа → тон → мышцы → силуэт

РАКУРС      yaw +0.5 (три четверти вправо)
            способ ответа этой вещи: черта поверхности

СОСТОЯНИЕ   headSize 0, volume 0, relief 0, gloss 0.45, matte 0.35
            свет: −0.34 / −0.38, контраст 0.55
            (только ручки, влияющие на выбранное)

ИСТОРИЯ     3 шага назад: volume +0.1 → откатил
                          gloss +0.2  → оставил
                          yaw 0 → +0.5

СНИМКИ      кадр целиком + вырез вокруг точки + тот же кадр «только свет»

ЗАПРЕТЫ     lock: [eyes, body]
            нельзя: LIGHT по частям, hex мимо палитры, свой силуэт
```

### Откуда берётся история — и это бесплатно

`setOverride(patch)` **заменяет патч целиком**, а не сливает
(`worm-renderer.js:2004`). Значит редактор обязан хранить накопленный
патч у себя. **Стопка накопленных патчей и есть история изменений** —
она возникает как побочный продукт правильной реализации, а не как
отдельная работа. Оттуда же бесплатно приходит откат.

### Почему это решает задачу агента

Сегодня агент получает строку и уходит читать десять файлов, чтобы
выяснить, какие числа вообще бывают. Со структурированным контекстом он
получает **закрытый список того, что можно крутить, и текущие значения**.
Разница та же, что между «почини машину» и «стучит правый передний,
пробег 80 тысяч, вот список подозреваемых узлов».

## 8. Максимально простой переход

Четыре шага. **Первые два не трогают ни одного существующего файла.**

### Шаг 1 — `worm-parts.js`: таблица сущностей
Чистые данные + функции `at()`. Ничего не рисует, ни на что не влияет.
Проверка: для каждой сущности `at()` возвращает точку внутри персонажа.

### Шаг 2 — `worm-inspect.js`: подсветка, два режима выбора, накладки
Слой **поверх** персонажа, вне `worm-root`. Только читает. Уже на этом
шаге появляется «показать проблему» и сбор контекста для агента —
самая полезная половина всей затеи, и она стоит дешевле всего.

### Шаг 3 — `worm-look.js`: пульт из первого отчёта + перетаскивание
Только здесь появляется запись. Ползунки и ручки пишут в накопленный
патч, патч уходит в `setOverride`/`setLivePose`. История и откат —
бесплатно.

### Шаг 4 — точечные правки в рендерере, и их ровно две
1. Экспортировать `skullHalf` из `WormSilhouette` (одна строка).
2. Per-side дельты ориентиров черепа (одно поле на ориентир, по
   умолчанию 0).

Обе — **аддитивные**. Ни один контракт не меняется: `data-part`,
`data-anchor`, публичный `handle` остаются как есть.

### Чем проверяется

`test-scars`, `test-wardrobe`, `test-tilt`, `test-no-words`,
`audit-frames` — все должны остаться зелёными на каждом шаге. Шаги 1–2
не могут их уронить по построению; шаги 3–4 могут, и именно там проверка
имеет смысл.

### Чего в плане нет намеренно

* Разреза `worm-head.js` и `tick()` — риск настоящий, для этих целей
  бесполезен.
* Разметки дерева именами — щеки в дереве нет, а править десять файлов
  ради остальных незачем.
* Переписывания анатомии — 83% анонимных узлов анонимны правильно.

## 9. Что может пойти не так

| риск | как проявится | что делать |
|---|---|---|
| подсветка на живом слое | просадка кадров при наведении | слой вне `worm-root`, без фильтров |
| `elementsFromPoint` на телефоне | стопка иная из-за масштаба холста | считать через `SvgSpace`, не через CTM |
| асимметричный череп | шрамы поедут | `test-scars.js` — он гоняет реальный контур |
| патч копится и расходится с моделью | «вчера было не так» | патч виден в инспекторе целиком, кнопка «сбросить» |
| агент крутит запрещённое | вернётся гирлянда из пластика | `lock` и список запретов — часть контекста, а не пожелание |

## 10. Одна метрика

Не строки кода. **Сколько шагов от «выглядит не так» до правки.**

Сегодня: заметил → угадал, какой файл → нашёл функцию → понял, какое
число → поправил → перезагрузил → посмотрел → повторил. Семь шагов,
чтение трёх файлов, и половина из них — угадывание.

После: ткнул → увидел имя и ручки → потянул → увидел. Четыре, и ни
одного угадывания.
