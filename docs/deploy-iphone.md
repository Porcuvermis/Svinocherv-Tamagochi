# Сборка на айфоне: как получать актуальную версию

Проект — чистая статика, «сборки» в смысле компиляции у него нет. Значит и
доставка на телефон должна быть простой: **любой пуш в любую ветку → через
минуту иконка на домашнем экране открывает эту самую правку**. Ниже как это
устроено и что нажать один раз, чтобы заработало.

Адрес игры: **https://porcuvermis.github.io/Svinocherv-Tamagochi/**

---

## Разовая настройка (одна галка, делается с телефона)

1. Открыть репозиторий → **Settings → Pages**.
2. В **Build and deployment → Source** выбрать **GitHub Actions**.

Всё. Первый же пуш запустит выкладку. Статус — во вкладке **Actions**.

## Разовая настройка на самом айфоне

1. Открыть адрес игры в **Safari** (именно Safari: добавлять на домашний
   экран умеет только он).
2. Кнопка «Поделиться» → **На экран «Домой»**.
3. Иконка запускает игру в полный экран, без адресной строки Safari.

## Как это работает дальше

* **Пуш в любую ветку** — и через ~40–60 секунд корень сайта отдаёт именно
  её. В корне всегда лежит ветка, в которую коммитили последней: смотреть
  правки надо сразу, а не после мержа.
* **Открыл иконку** — приложение проверяет обновление при каждом появлении
  на экране. Если сборка новая, страница сама перезагрузится на неё. Раньше
  это и выглядело как «игра загрузилась два раза»: экран успевал показать
  игру, а потом перезагружался под свежую сборку. Теперь проверка идёт под
  чёрной пеленой экрана загрузки (`src/core/boot-screen.js`), и перезагрузка
  случается до того, как игрок что-то увидел. Если сборка приезжает уже
  на ходу — экран сначала уходит в чёрное, потом перезагружается.
* **Нет сети** — игра открывается из кеша (метро, лифт, самолёт). Как только
  сеть появилась, снова берётся свежая версия: кеш здесь страховка, а не
  источник правды. Внешних зависимостей нет: three.js лежит в репозитории,
  поэтому и первый запуск без сети не разваливается.

### Белая вспышка при запуске

Между анимацией открытия иконки и первым кадром страницы iOS показывает свой
launch-экран. Своей картинки для него у игры сначала не было, и система
показывала белый — отсюда вспышка белым перед чёрной пеленой загрузки. CSS
тут бессилен: страница в этот момент ещё не разобрана.

Лечится единственным способом — готовыми картинками: `icons/splash/*.png`,
сплошь чёрные, того же цвета, что и пелена. iOS выбирает картинку по точному
размеру устройства, поэтому их много (по файлу на модель). Генерируются
скриптом, руками не правятся:

```
python3 tools/make-splash.py
```

Скрипт печатает готовые `<link rel="apple-touch-startup-image">` — их и надо
положить в `<head>` index.html. Появился айфон с новым разрешением — строка в
таблицу `DEVICES` внутри скрипта.

Если вспышка осталась: удалить иконку с домашнего экрана и добавить заново —
launch-экраны iOS запоминает при установке.

### Проверить, какая версия открыта

Три способа, от быстрого к самому надёжному:

1. **`<адрес игры>/build.txt`** — две строки: номер сборки и имя ветки.
   Сравнить с тем, что показывает игра.
2. **Кнопка 🐞 (debug-режим)** — в левом нижнем углу появится штамп с
   веткой и версией: `claude/что-то · 20260822-1850-abc1234`.
3. **Конец хеша** в номере сборки — это первые 7 символов коммита. Видно, из
   какого именно коммита собрано.

Номер сборки выглядит так: `ГГГГММДД-ЧЧММ-<хеш коммита>`, время UTC.

### Если обновление всё-таки застряло

Открыть игру с параметром **`?sw=off`**:

```
https://porcuvermis.github.io/Svinocherv-Tamagochi/?sw=off
```

Это сносит service worker и все кеши, показывает «Кеш очищен». После этого
открыть обычный адрес — загрузится с нуля. Аварийный выход на случай, когда
под рукой только айфон и никакого devtools.

## Что заменило ручные `?v=`

Раньше версии ассетов правились руками:

```html
<link rel="stylesheet" href="style.css?v=13">
<script src="src/core/worm-renderer.js?v=32"></script>
```

Пятнадцать файлов, каждый со своим номером. Забыл поднять номер после
правки — Safari отдаёт файл из кеша, а на экране вчерашний код: правка вроде
запушена, но её не видно, и непонятно, где искать причину.

Теперь при деплое **все `?v=...` получают один общий номер сборки**. То есть:

* номера в `index.html` **можно не трогать** — они перезаписываются;
* новый пуш = новые URL у всех ассетов = кешу нечего подсунуть старого;
* в репозитории номера остаются как есть, подмена происходит только в
  выложенной копии.

Добавляешь новый файл — просто подключай его как обычно, с любым `?v=`:

```html
<script src="src/minigames/new/new.js?v=1"></script>
```

## Ветки: что где лежит

Мержить ради «посмотреть» не нужно вообще. Раскладка такая:

* **Корень сайта** — ветка, в которую коммитили последней. Это то, что
  открывает иконка с домашнего экрана. Запушили в `claude/новая-фича` —
  через минуту иконка показывает её.
* **`/preview/<ветка>/`** — каждая ветка отдельно, включая `main`. Нужно,
  только если надо вернуться к конкретной, а не к самой свежей.
* **https://porcuvermis.github.io/Svinocherv-Tamagochi/preview/** — список
  всех сборок: имя ветки, «5 минут назад», описание коммита. Помечено, какая
  из них сейчас в приложении.

Адрес превью собирается из имени ветки: `claude/новая-фича` лежит в
`/preview/claude-новая-фича/` (слэши и подчёркивания превращаются в дефисы).
Но проще открыть список и ткнуть.

Тогда зачем мерж в `main`. Затем же, зачем он нужен всегда: зафиксировать,
что правка принята. На то, что видно с телефона, он больше не влияет —
`main` в этой схеме просто одна из веток, которая обычно старше остальных.

Устройство:

* Сайт у Pages один, поэтому каждый деплой пересобирает его целиком: свежая
  ветка в корень плюс превью десяти последних по времени веток.
* Удалил ветку — её превью пропадает при следующем деплое само.
* Ветка без `index.html` в превью не попадает.
* Выкладку запускают два workflow, а не один. GitHub разрешает публиковать
  Pages только с ветки по умолчанию: пуш в любую другую ветку отлетает с
  «environment protection rules», не начав работу. Поэтому пуш ловит
  пустышка `pages-trigger.yml`, а она через `workflow_run` запускает
  `deploy-pages.yml` — событие `workflow_run` выполняется от имени ветки по
  умолчанию и ограничение проходит. Если снять ограничение руками
  (Settings → Environments → github-pages → Deployment branches), пустышку
  можно удалить, а деплою вернуть обычный `on: push`.

## Файлы, которые за это отвечают

| Файл | Зачем |
|---|---|
| `.github/workflows/pages-trigger.yml` | Ловит пуш в любую ветку и запускает выкладку |
| `.github/workflows/deploy-pages.yml` | Собирает и выкладывает на Pages, подставляет номер сборки |
| `boot.js` | Определяет версию, регистрирует service worker, аварийный `?sw=off` |
| `sw.js` | Network-first кеш: свежесть в приоритете, офлайн как страховка |
| `manifest.webmanifest` | Имя, иконка и полноэкранный режим на домашнем экране |
| `icons/*.png` | Иконки; пересобираются `python3 tools/make-icons.py` |
| `tools/preview-index.sh` | Вёрстка страницы со списком сборок |
| `vendor/three.min.js` | three.js r128 локально: без него «Зависть» зависела бы от чужого CDN |
