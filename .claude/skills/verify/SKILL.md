# Проверка правки

Правка, которую не открыли в браузере, не проверена (CLAUDE.md, разд. 3).
Тесты ловят «дошло ли до конца», а не «выглядит ли это игрой».

## Снимки

```bash
python3 -m http.server 8777     # из корня, один раз на сессию
SIN=pride SETUP='Backend.grantCurrency("pride_kiss",2000)' \
STEPS='[["a",""],["b","PrideMinigame.openStore(\"boost\")"]]' \
  NODE_PATH=/opt/node22/lib/node_modules node tools/shot-sin.js /tmp/s-
python3 tools/sheet.py /tmp/s- 4 260       # смотреть ЛИСТ, не кадры по одному
```
* `tools/shot-sin.js` — любой грех, шаги кодом; `DPR=2` — крупно для
  деталей (потом обрезать нужный кусок PIL'ом).
* **Середина анимации — заморозкой, а не «как успел снимок»:** шаг
  `["mid","freeze:300",50]` ставит css-переходы на 300 мс. Программная
  видеокарта медленная, и обычный снимок врёт о времени. Ждать после
  заморозки мало (50 мс): таймеры игры продолжают идти.
* Свет шейдером в прогоне виден (swiftshader), скорость — нет.

## По-айфонски (всё, что водит пальцем)

`SVINO_VIEWPORT=390x700 SVINO_FAKE_CTM=1` к прогону. Тапы считать через
`SvgSpace.toClient`, не через `getScreenCTM` (иначе прогон сам промахнётся).
Проверять: нажатия попадают, слои (html поверх svg) встают ровно на место.

## Тесты

`node tools/q.js <тест>.js` (только провалы; `VERBOSE=1` — разобрать).
Таблица — `tools/README.md`. Всегда, если менялся интерфейс:
`test-no-words.js` (инвариант 9) и тест своего греха. Поменял интерфейс —
поправь тест под новые классы, а не выкидывай проверку. Плавающий провал —
сначала проверить, был ли он до правки (`git stash`), и не выдавать за свой.

## Скорость и слои (лампочки)

* Бесконечная css-анимация внутри общего svg красит его весь каждый кадр
  (ловушка 37) — не заводить.
* Уехавшее за край — прятать (`visibility: hidden`, ловушки 38, 57);
  `will-change` — только на время переезда (56).
* Тяжёлое (растр SVG, WebGL) — под покровом перехода, контексты отдавать.
* Под 4× замедлением (CDP `Emulation.setCPUThrottlingRate`) не тормозит —
  хватит, дальше не удешевлять.
